at `2e7f4a3` contains the reviewed child-paced grouping, visible vertical exchanges,
25-example concept curriculum and real-system Reduce Motion acceptance suite.
The candidate also contains ten-frame visibility/presentation corrections and
the model-only countable multiplication/division adapter. Ten-frame source review is complete; native acceptance, including committed-

## Why separate commands

The digest-verified prior standard command at `37256a7` took 495.64 seconds for
248 methods. The current `9fc16d6` standard command took 862.53 seconds, including
all 15 UI methods (517.516 seconds) and 245 components. It finished with one
fixture exception, not a timeout: the paused-presentation test illegally changed
`scrubsLinearly` after pausing. Its summary reports 259 Passed, one Failed and no
skips; this is diagnosis of the failed run, not a strict successful execution proof.
Over four minutes preceded its first component suite; the exact startup cause is
not established. This observed combined-command budget justifies separating
components from UI rather than enlarging the bound or silently selecting less.

The current compact command took 493.10 seconds for eight methods. These are
measured earlier-source timings, not a guarantee for the new teaching flows.
Authored concept core and division plans reserve 4–7 and 3–6
minutes separately, so combining them risks the unchanged 900-second ceiling.
Focused grouping and real Settings navigation are also unmeasured native work.

## Real preferences and exact proof

`configure` still verifies the actual system Dynamic Type setting by CLI help,
query, setter and exact readback. Its status explicitly refers to Dynamic Type
only. `systemSettingsIntent` describes the Reduce Motion test's plan, never a
verified preference. Only the dedicated `reducedMotion` lane selects that test;
it must confirm ownership, navigate actual Settings, retain exact switch values,
exercise genuine renderer states and restore the original switch value.

Normal-motion tests require natural completion, not Reduced Motion or a static
settled endpoint. Every selected case must occur once, Passed, in the exact
structured xcresult target on its owned device. No skipped or missing case can
satisfy acceptance: the strict proof rejects every such result. Motion-only
fixtures retain explicit system-Reduce-Motion skip guards for local test runs;
those guards cannot turn this acceptance lane green. No console/aggregate
fallback, timeout inflation, simulator resets or automatic retries were added.

After native execution, retain and inspect the original videos and screenshots,
including first play, Replay, wrong-choice feedback, late recipients/bags,
maximum text, landscape and actual Settings restoration. Until then, the richer
teaching source and all new UI flows remain unaccepted.

## Baseline selector correspondence

The earlier visible-teaching integration document records two intentional
vertical-test renames. The complete candidate preserves those and adds one
explicit ten-frame contract replacement:

- `VerticalArithmeticBoardViewTests/testReduceMotionStaticRenderHasSameCountsAndNoTransfers`
  → `VerticalArithmeticBoardViewTests/testMotionDisabledStaticRenderHasSameCountsAndNoTransfers`.
  Synthetic static rendering is not proof of the actual system preference.
- `VerticalTeachingViewportTests/testReplayPreservesTheChosenInspectionOffsetAndStep`
  → `VerticalTeachingViewportTests/testReplayRecoversTheEntireConcreteExchangeWithoutChangingTheStep`.
  Clipped actions must be reframed; the separately selected already-visible
  exchange test retains the exact safe-offset contract.
- `LessonIntroViewTests/testShortCompactNextFramesTheWholeCounterTransformationWhenAnnotationsDoNotFit`
  → `LessonIntroViewTests/testShortCompactCounterOnlyFitStaysStaticUntilTheWholeAnnotatedActionCanFit`.
  Fitting counters alone is no longer sufficient for moving instruction. The
  replacement preserves static counts, selected step and inspection position,
  and requires the honest visibility-paused state. The separately selected
  `testImpossibleSceneOnlyResumesAfterExpansionAndExplicitReplay` checks
  expanded-but-still-static recovery followed by explicit, fully visible Replay.

There are no other missing baseline selectors. All replacements are selected;
none is an exclusion or a substitute for the pending native presentation proof.
